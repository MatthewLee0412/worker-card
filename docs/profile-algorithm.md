# 人才画像评分算法说明（v2）

> 本文档说明 Worker Card 人才棒球卡的画像计算方式。核心思想一句话：
> **让画像在证据不足时"保持谦逊"，在证据充分时"敢于下结论"，且每个派生数字都能向员工解释清楚来源。**

实现位置：`public/profile.js`（纯函数模块，浏览器与 Node 共用）+ `public/app.js` 的 `talentProfile()` 适配层。
所有计算仍只发生在前端，服务端只保存原始观察证据，数据格式零改动。

---

## 一、设计原则

1. **可解释性优先**：工具的使用者要向员工解释画像，所有公式必须能用一句话说清。
2. **保守优于冒进**：宁可显示"样本不足"，也不凭 1~2 条证据给人贴"核心优势"标签。
3. **证据是依据**：原始观察记录永不修改，画像只是证据的聚合视图；删除记录后全画像自动重算。

---

## 二、维度分：贝叶斯收缩

### 2.1 公式

```
score* = ( Σsᵢ + k·μ₀ ) / ( n + k )
```

等价变形（更好理解）：

```
score* = (n/(n+k)) · s̄ + (k/(n+k)) · μ₀
```

即 **"证据均分"与"先验均值"按 n : k 加权平均**。

> v3 起，n 与 s̄ 先经时间衰减折算为有效证据量 n_eff 与加权均分（见第六节），公式结构不变——把"每条证据 1 票"改成"每条证据按新鲜度折算票数"。

### 2.2 参数含义

| 符号 | 含义 | 取值 |
| --- | --- | --- |
| sᵢ | 该维度第 i 条真实观察的评分（1~5 整数） | 来自 `assessments.json` |
| n | 该维度的真实证据条数 | 动态计算 |
| μ₀ | **先验均值**：没看任何证据时的默认分 | **3**（"可以独立完成"，中性锚点） |
| k | **先验强度**：相当于假设已有 k 条 μ₀ 分的虚拟证据 | **3** |
| score* | 收缩后的维度分（后验均值） | 计算结果 |

直觉：像开会投票——真实证据 n 票 + 虚拟中性票 k 票，最终得分是全部 n+k 张票的平均分。
证据少时虚拟票占主导（分数被拉向 3 分），证据多时真实票接管。

### 2.3 为什么先验取 3、k 取 3

- **μ₀ = 3**：1~5 的中点，语义上恰好是"可以独立完成"，不带褒贬。对没有记录的人，最诚实的假设就是"能独立做常规工作"，而不是 0 分或 5 分。
- **k = 3**：k 决定"需要多少真证据才能推翻先验"。当 n = k 时真实与先验票数相等（score* 恰为两者中点），所以 **k = 3 意味着第 4 条真实证据开始占主导**。

### 2.4 常用查表（μ₀=3，k=3，假设证据均为近期记录；旧证据按第六节衰减折算）

| 证据情况 | 简单平均 | 收缩分 | 结论 |
| --- | --- | --- | --- |
| 1 条 5 分 | 5.00 | **3.50** | 过 3.5 线但被 n≥2 门槛拦截 → "样本不足" |
| 1 条 4 分 | 4.00 | **3.25** | 回到待验证区间 |
| 1 条 2 分 | 2.00 | **2.75** | 低分也不会一条证据就定罪 |
| 3 条全 4 分 | 4.00 | **3.50** | 恰好压线入列，合理 |
| 3 条全 5 分 | 5.00 | **4.00** | 敢给高分了 |
| 6 条全 4 分 | 4.00 | **3.67** | 证据越多越接近真实均分 |
| 12 条全 4 分 | 4.00 | **3.80** | 仍达不到 4.0（见 2.5） |

### 2.5 一个值得注意的性质

即使 12 条证据全是 4 分，收缩分也只有 3.80。想让维度显示 4.0+，必须是
"3 条全 5 分"或"长期均分 4.2 以上"。这与评分口径中"4 = 稳定优秀"的语义咬合：
**普通的好不足以宣称优秀，持续大量的好或凤毛麟角的顶尖表现才行。**
这是收缩带来的"免费"校准。

### 2.6 调参

k 没有数学上的唯一正确答案，是风险偏好：

| k | 效果 |
| --- | --- |
| 2 | 画像更灵敏，2 条证据基本接管 |
| **3（默认）** | 第 4 条证据开始占主导，攻守平衡 |
| 5 | 更保守，需要 6 条证据才接管 |

改法：只改 `public/app.js` 顶部 `PROFILE_OPTIONS.prior.strength` 一个常量，其余逻辑不用动。

## 三、优势 / 关注方向：双重门槛

两个机制各管一件事，互相咬合：

| 机制 | 作用对象 | 规则 |
| --- | --- | --- |
| **收缩（公式）** | 分值 | 证据越少，分数越靠近 3 分，不会被少量证据吹高或砸低 |
| **门槛（n≥2）** | 展示 | 证据不足 2 条的维度**不允许**进入优势/关注方向列表 |

具体规则：

- **优势**：该维度证据 n ≥ 2，且收缩分 ≥ **3.5**，取前 3。
- **关注方向**：该维度证据 n ≥ 2，且收缩分 < 3.5，取最低前 2。标注"不是负面标签"。
- **样本不足**：0 < n < 2 的维度显示"样本不足，继续观察"，中性灰色，不进入任何列表。
- **证据不足**：n = 0 的维度显示"—"，与低分是两回事（沿用 v1 设计）。

典型配合：1 条 5 分 → 收缩压到 3.50（分数诚实）+ 门槛拦截（结论诚实），双保险。

## 四、可信度：三因子模型

### 4.1 公式

```
confidence = 100 × ( 0.4 × 样本量 + 0.3 × 维度覆盖 + 0.3 × 评价人多样性 )

样本量        = min( 证据总条数 / 12 , 1 )
维度覆盖      = 有分数的维度数 / 6
评价人多样性  = min( 不同评价人数 / 3 , 1 )
```

### 4.2 为什么不用"数条数"

v1 只看记录总数：6 条记录全记在同一维度、全是同一个人评的，也会显示"较稳定"——
样本量虚高但信息维度单一。三因子要求**量、广度、独立性**同时达标。

### 4.3 分级

| 分数段 | 标签 |
| --- | --- |
| [0, 30) | 待建立 |
| [30, 55] | 初步画像 |
| (55, 80) | 形成中 |
| [80, 100] | 较稳定 |

### 4.4 示例

- 张三：3 条证据、覆盖 3/6 维、3 位评价人
  → 100 × (0.4×0.25 + 0.3×0.5 + 0.3×1) = **55 → 初步画像**（v1 按条数会给"形成中"，新算法更诚实）
- 12 条证据、覆盖 6/6 维、3 位评价人 → **100 → 较稳定**

UI 上三个子指标（样本 / 覆盖 / 评价人百分比）以提示框形式展示在可信度标签上，可信度本身可解释。

## 五、盲区提示：自评 vs 他评

数据已区分自评与他评，v2 开始利用这一信息。

**触发条件**（同时满足）：

1. 该维度自评、他评均存在；
2. 他评条数 ≥ 2；
3. |自评均分 − 他评均分| ≥ 1。

**展示文案**：

- 自评更高：`自评高于他评 x.x 分——可能存在认知盲区，建议一对一沟通核对`
- 他评更高：`自评低于他评 x.x 分——自我要求可能高于团队共识，也值得核对`

这是"激进面对事实"的直接落地：认知偏差本身成为画像的一条证据。

## 六、时间衰减与近 90 天趋势（v3）

### 6.1 衰减：给证据按"新鲜度"折算票数

```
w      = 0.5^(距今天数 / 180)        半年半衰期：当天权重 1，180 天减半，360 天剩 0.25
n_eff  = Σwᵢ                         有效证据量：旧证据折算成"不到一条"
score* = ( Σ(wᵢ·sᵢ) + k·μ₀ ) / ( Σwᵢ + k )
```

旧证据**双重衰减**：分子占比小，且 n_eff 小、先验话语权回升。两条两年前的 5 分记录，
n=2 仍过门槛，但 score* ≈ 3.2，自然失去优势资格——不需要为"陈旧"单独写规则。

**n≥2 门槛仍按真实条数 n**（管"观察次数够不够"），衰减压权重（管"旧证据多少算数"），两个机制不混。

### 6.2 趋势：近 90 天 vs 之前（只播报事实，不影响分数）

- 窗口内 ≥1 条 → 显示 `近90天 x.x`；趋势是事实播报而非判断，刻意不做收缩。
- 两侧各 ≥2 条且 |差| ≥ **0.5** → 加箭头（↑/↓）；delta 恰为 0.5 显示箭头。
- 窗口内往往只有 2~3 条证据，均分噪声大，阈值以下的差距视为抽样偶然，不画箭头。

### 6.3 陈旧提示：防"僵尸画像"

衰减的副作用：**停止记录后，画像会随时间自然向 3 分褪色**——理念上正确（人会变，过期卡片比没有更危险），
但分数自己变动会让用户困惑。因此最新证据距今 > **180** 天时，画像弹窗与卡片提示
"画像可能过时，建议安排一次观察"。可信度三因子本期不动，用陈旧提示覆盖时效问题。

### 6.4 边界与可测性

- 未来日期（手滑/时区）钳制为当天，权重不超 1；日期解析失败按当天处理。
- 窗口含恰好 90 天的证据（age ≤ 90 算窗口内）。
- `now` 由参数传入（测试固定日期），默认取当前时间，保证纯函数可单测。

## 七、数据流与不变量

```
assessments.json（原始证据，只增不改正文）
        │
        ▼
ProfileMath.buildProfile(records, COMPETENCIES, options)   ← public/profile.js 纯函数
        │
        ▼
{ dimensions[], strengths[], development[], insufficient[],
  confidenceScore/Label/Parts, overall, blindspot... }
        │
        ▼
app.js 渲染（卡片 + 画像弹窗）
```

不变量：

- 删除/新增观察后，画像完全由当前证据集合重新计算，无缓存、无漂移。
- `buildProfile` 是纯函数：同样的输入必得同样的输出，可用 `node:test` 单测（见 `test/profile.test.js`）。
- 时间衰减与近 90 天趋势（v3）已上线，见第六节。
