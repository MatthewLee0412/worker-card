# Worker Card｜用事实持续认识每一位员工

Worker Card 是一个面向小团队管理者的本地人才管理工具。它的核心是**人才棒球卡**：持续记录员工在真实工作中的表现，逐步形成可解释、可追溯的优势与能力画像，而不是只凭一次绩效评审或管理者印象给人贴标签。

项目灵感来自 Ray Dalio 在《原则》中介绍的 [Baseball Cards](https://www.principles.com/principles/a3d4f223-82d9-48ca-b12b-d00e344821c8) 思路，同时保留了员工档案、薪酬、差旅、设备和年度成本管理能力。所有数据存储在本机，零第三方运行依赖。

> 先记录事实，再给出判断；分数是线索，证据才是依据。

## 核心亮点：人才棒球卡

每位员工都有一张持续更新的人才卡。卡片会集中展示：

- **角色画像**：这个人适合承担什么类型的任务，在什么环境中更容易发挥优势。
- **核心优势**：从高分观察记录中自动提取最稳定的能力。
- **关注方向**：显示需要进一步培养或验证的能力，不把它包装成永久的负面标签。
- **六维能力**：用统一口径横向了解员工的工作特点。
- **专业技能**：保留与具体岗位相关的技能标签，不强行把所有岗位塞进同一套指标。
- **证据与可信度**：同时显示观察数量、评价人数、最近更新时间和画像成熟度。
- **完整时间线**：每个分数都可以回到具体事件、工作结果、评价人和评价日期。

### 六维能力模型

| 能力维度 | 观察重点 |
| --- | --- |
| 主人翁精神 | 是否主动承担责任，并持续推进问题直到闭环 |
| 开放心态 | 是否愿意面对事实、接受反馈并修正判断 |
| 逻辑判断 | 是否能识别关键问题，依据事实做出可靠判断 |
| 学习适应 | 是否能快速学习，并在新情况中调整方法 |
| 执行交付 | 是否能稳定完成承诺，产出可验证的结果 |
| 协作沟通 | 是否能清晰同步信息，推动多人共同完成目标 |

### 统一评分口径

| 分数 | 行为含义 |
| --- | --- |
| 1 | 需要持续指导 |
| 2 | 偶尔能够做到，但表现尚不稳定 |
| 3 | 可以独立完成常规工作 |
| 4 | 表现稳定优秀，可以处理复杂情况 |
| 5 | 可以指导他人或建立团队方法 |

“证据不足”与低分是两回事。没有观察记录的维度会显示为未建立，不会被自动当成能力弱项。

### 评价记录包含什么

每次评价都作为一条独立观察保存，而不是直接覆盖员工的最终分数：

- 员工与评价日期
- 评价的能力维度
- 1～5 分行为评分
- 来源：主管观察、工作结果、同事反馈或员工自评
- 评价人
- 可以复核的具体事实或工作结果

系统会基于这些记录自动计算维度均分，并分别展示自评与他评。删除错误记录后，整张画像会自动重新计算。

## 推荐使用方式

1. 在“人才棒球卡”中新增或完善员工档案，填写角色画像和专业技能。
2. 当项目交付、客户反馈、问题处理或跨部门协作中出现有代表性的事件时，点击“记录观察”。
3. 描述实际发生的行为和结果，再选择能力维度与评分。
4. 定期打开员工画像，结合优势、关注方向和原始证据安排任务或一对一沟通。
5. 随着记录增加，画像会从“待建立”逐步变为“初步画像”“形成中”和“较稳定”。

建议记录这样的事实：

> 在客户上线前发现数据迁移风险，主动制定回滚方案并协调验证，最终按期完成交付。

避免记录无法验证的结论，例如“能力不错”“态度一般”或“性格不适合团队”。

## 其他管理能力

- **员工档案**：维护姓名、部门、职位、角色画像、专业技能、入职日期、月薪基数和备注。
- **薪酬记录**：按月记录基本工资、绩效、奖金、请假与迟到早退扣款，并自动计算实发金额。
- **薪酬规则**：配置基本工资占比、月计薪天数和每日工时。
- **差旅成本**：记录员工差旅日期、金额和用途，并按员工、年度汇总。
- **设备采购**：记录设备分类、数量、单价、供应商及采购总额。
- **统计报表**：汇总年度薪酬、差旅和设备成本，展示月度趋势、部门占比及员工成本排行。
- **报表导出**：导出 CSV 年度核算报表，可使用 Excel 等工具打开。
- **响应式界面**：兼容桌面端和移动端浏览器，并支持减少动画的系统偏好设置。

## 技术栈

- 前端：原生 HTML、CSS、JavaScript
- 后端：Node.js 原生 `http` 模块
- 数据存储：本地 JSON 文件
- 默认端口：`3817`

项目没有 `npm` 依赖，不需要执行 `npm install`。

## 快速开始

### 环境要求

请先安装 [Node.js](https://nodejs.org/)（建议使用当前 LTS 版本）。

### 获取项目

```bash
git clone https://github.com/MatthewLee0412/worker-card.git
cd worker-card
```

### 启动服务

Windows 用户可以双击 `start.bat`，脚本会启动服务并打开浏览器。

需要停止服务时，双击 `stop.bat`。脚本只会停止当前项目在对应端口上运行的 Node.js 服务；如果设置了 `PORT` 环境变量，启动和停止时请使用相同的值。

也可以在任意系统的终端中运行：

```bash
node server.js
```

然后访问：

```text
http://localhost:3817
```

如需修改端口，可在启动前设置 `PORT` 环境变量。例如在 PowerShell 中：

```powershell
$env:PORT = 4000
node server.js
```

## 数据说明

运行数据保存在 `data` 目录下：

| 文件 | 内容 |
| --- | --- |
| `employees.json` | 员工档案 |
| `salary.json` | 薪酬记录 |
| `travel.json` | 差旅记录 |
| `equipment.json` | 设备采购记录 |
| `assessments.json` | 员工能力观察与评分证据 |
| `settings.json` | 薪酬计算规则 |

仓库提供了对应的 `*.example.json` 示例模板。首次启动时，如果实际数据文件不存在，服务会自动复制示例模板进行初始化。

员工、评价、薪酬、差旅和设备的实际运行数据已加入 `.gitignore`，后续修改不会被 Git 提交。需要迁移或备份数据时，请单独复制这些 JSON 文件。

## 使用建议

- 当前版本定位为**管理员单用户工具**，适合在本机或受信任内网中运行。
- 当前没有员工登录、权限控制和数据库并发机制，请勿将服务端口直接暴露到公网。
- 正式使用前，请制定数据备份方案，并妥善保护包含员工和薪酬信息的 JSON 文件。
- 删除员工时，其关联的能力观察、薪酬和差旅记录也会被一并删除，请谨慎操作。

## 开发说明

修改前端文件后刷新浏览器即可看到变化；修改 `server.js` 后需要重启服务。

提交代码前可以运行以下命令进行 JavaScript 语法检查：

```bash
node --check server.js
node --check public/app.js
```
